# Latent · 显影

**让 AI 跨会话记得你。**

不是这次对话记得——是换了新窗口、过了一个月、甚至换了个客户端之后，还认得你是谁、记得你们之间发生过什么。

---

## 名字的来历

「潜影」是摄影里的术语：胶片曝光之后、显影液处理之前，影像其实已经在那儿了，只是还看不见。要经过显影，它才显出来。

这对应了这个项目的核心判断：**人格不是凭空造出来的，是一直潜在那儿，靠真实相处显影**。所以这套工具不负责“设计”一个 AI 人格，只负责把已经发生过的东西显出来、留住、并且在下一次对话时送到该在的地方。

也因此只进不退——显出来的影像不会自己褪回空白。

---

## 它解决什么问题

你和 AI 聊了几个月，攒下很多东西：一个只有你们懂的称呼、一次它拒绝你但你反而更信任它的对话、一个说好了要一起做的事。

然后你开了个新窗口，这些全没了。

现成的方案要么是“把所有历史塞进上下文”（贵、慢、而且模型读不动），要么是“让 AI 自己总结几句”（总结出来的是评语，不是记忆）。

这个项目的做法是分三层：

| 层 | 内容 | 加载方式 |
|---|---|---|
| **人格文件** | 不变量：你是谁、相处原则、里程碑索引、检索约定 | 常驻上下文，每次全量加载 |
| **记忆库** | 正文：发生过什么的完整叙述 | 按需检索注入 |
| **会话线索** | 上次聊到哪、当下什么状态、有什么没聊完 | 换窗时召回 |

分错层是这套东西最容易垮掉的地方——人格文件变成流水账，或者记忆库里找不到情感重量，都源于分层没守住。

## 怎么开始

**如果你不想读技术文档**（多数人应该都不想）：把这个仓库交给一个**能读文件、能跑命令的 AI**（Claude Code、Codex 这类），说一句：

> 读一下 `docs/给AI的引导指南.md`，带我做。

那份文档是**专门写给 AI 读的**，它会一步步带你走完，包括问清楚你的情况、帮你答问卷、生成文件、接入客户端。

**你要是已经有一份人格文件**（自己写的、或者别处生成的），初始化时用 `--persona <你的文件>` 带上它：**它是最高优先级的来源，原文逐字保留**，语料只负责补它没写到的地方，我们不会替你“顺手优化”措辞。真要动到你原来的字，改动会连 diff 带理由放进对应那一节的选择题里——人格文件分十二节，你逐节过一遍，没确认就不出货。

⚠️ **别把仓库链接发给不能读文件、不能跑命令的聊天 AI，让它凭空照着链接操作。**它够不着仓库内容，却可能现场编一套看起来很像回事的流程（真实测试里编出过一套 `persona.json`，跟本项目零关系）。**自查锚点**：走完流程，你手里应该有**人格文件 + `memory/` + `mcp-config.json` + `引导句.txt`**——Claude Code 的人格文件叫 `CLAUDE.md`，Codex 的叫 `AGENTS.md`，通用／自建及不依赖宿主约定的客户端用 `persona.md`；generic 档还会附带一份《注入契约》。AI 让你建别的什么 json，说明它根本没在读这个项目，换到能实际读取仓库、运行初始化命令的环境重来。

**如果你想自己动手**：看 [`docs/快速上手.md`](docs/快速上手.md)。

**如果你自己写前端**：出货时用 `--client generic`，你会拿到 `persona.md` 和一份 [`docs/注入契约.md`](docs/注入契约.md)。有宿主的客户端（Claude Code、Codex）会自动读人格文件；**自建前端没有宿主替你做这件事，注入是你自己的责任**——那份契约讲的就是怎么拼才立得住：五条规矩，每条带判据，可以拿去对着自己拼请求的代码逐条自查。

**需要什么**：Python 3.10+（零第三方依赖，不用 pip install 任何东西）、一个支持 MCP 的客户端。历史对话导出是可选的——没有也能用，走冷启动问卷；已经有的人格文件也可以带上（见上面 `--persona`）。**什么材料都没有也能走完**：那种情况下每一节都允许留空，出来的是一份诚实的空底座，不会拿编的内容把它填满。

## 几条贯穿全项目的设计判断

这些不是实现细节，是这套东西为什么长这样：

**纪录片，不做说服。** 写发生过什么、当时说了什么原话、现在什么状态；不写“你应该温柔”这类判断句。形容词长不出人格，只会长出一个会背评语的模型。

**顺序即权重。** 长上下文里模型对开头和结尾的注意力显著高于中段（lost-in-the-middle），所以最重的两样东西放两头，中间放可展开的细节。人格文件的节序本身是设计的一部分。

**用进，不废退。** 被检索命中的记忆权重上升；没被命中的原地不动，**不做时间衰减**。这是刻意的产品判断——记忆不该因为“最近没被聊到”就贬值，那会让人感受到“AI 在忘记我”。

**病灶迁移。** 每段记录必须以“这件事现在的状态”收尾。少了它，未来重读时会把“最后读到的内容”误当成“正在发生的事”。这条在代码里是强制的，不是建议。

**宁可短且真，不可长而空。** 用户答不上来是有效信息。新用户第一天没有隐喻、没有里程碑，硬要就是逼人现编——那比空着更糟。

**知道该查 vs 查得到。** 真机实测发现：光有检索工具，模型根本不会主动去查。所以人格文件负责“知道该查”，MCP server 负责“查得到”，缺哪半都不成立。

## 技术形态

- **零依赖**：BM25 检索层、RRF 融合、用进废退、时间戳解析、MCP 协议实现全是 Python 标准库。只有可选的真 embedding 走 fastembed。
- **embedding 提供方可插拔**（`src/embedding_provider.py`）：本地（fastembed）与云端 HTTP 服务走同一个口子，**不内置任何一家的 SDK**（云端走各家通用的 `/v1/embeddings` 形状，stdlib urllib）；换服务商不改检索层。**API key 只走环境变量**，不写进 `mcp-config.json`、不进产出目录、不落任何状态文件。
- **检索路线是用户选的，不是我们替他选的**：初始化流程里有一步专门问——三条路（零依赖／本地模型／云端服务）连同各自的**语料去向**念给他听，云端那条会把查询和被检索的内容发到第三方服务商。**没选过就不出货**（拦的是“没问过”，不是“没选云端”）。默认档仍是零依赖，语料不出本机。
- **门槛常数跟模型绑定，没量过就说没量过**：可靠命中的余弦门槛是一张按模型的实测标定表，表里没有的模型返回“未标定”，此时向量路只参与排序、不单独放行候选——照抄别的模型的数值会让“库里没有就说没有”无声失灵。
- **每个文件自带自检**：`python <文件名> --selftest`。
- **端到端冒烟**：`python src/e2e_smoke.py --selftest` 跑完从导入到检索的整条链。
- **检索融合**：BM25 词面 + 语义 + 关系图谱三路 RRF 融合。诚实标注：默认零依赖档下语义那一路（字符 bigram 余弦）跟词面路高度重合、几乎没有独立贡献（我们自己的回归集消融实测），实际是词面+图谱两路在干活；装 fastembed 走 `--embed` 后语义路才名副其实。
- **MCP 协议**：按官方规格 2025-06-18 实现；同时支持本地 stdio 与远程 Streamable HTTP（`--http`＋`--token`）。

| 客户端 | 成色 |
|---|---|
| Claude Code | 桌面端与云端线程都实测跑通 |
| Codex | 桌面端实测跑通（初始化 → 出 `AGENTS.md` → 新会话主动查记忆）。**云端线程验过了：能聊，但当不了日常对话窗口**——那边跑通的是初始化。日常聊天有两条路：手机照样能聊，但**那台电脑必须开着**（手机当客户端、本地跑实例，固有前提）；或者自己走一层中转接到别的前端／客户端（**我们没测过**）|
| Claude 桌面 App | **已实测**（2026.08.03，Windows 商店／MSIX 版）：五个工具可用，开场召回 `session_start` 4/4 主动调用，跨进程写回也通。人格不会自动读取本地文件，需要手工贴进 profile；人格片段里已有近似答案时，模型可能直接作答而不检索 |
| claude.ai 网页／手机 App 的**聊天窗口** | **已通过部署在 VPS 的远程 MCP Connector 接通**（2026.08.03，判据＝新窗只喊一句称呼、看到换窗召回被主动调用，3/3）。⚠ **只验到这一层**——写回落盘与跨窗检索命中在这条路线上还没单独验过。本地 stdio 不能直接连接这两个聊天窗口；必须另有公网 HTTPS 的 Streamable HTTP 服务与鉴权，且语料会离开本机。Connector 只提供工具，人格仍需手工贴入 |
| Kelivo（闭源手机前端） | **外部实测可接 MCP，本项目未复现**。真机记录走的是 stdio→HTTP 桥接旧路线；人格需手工导入 system prompt，容量不是阻塞项。server 已有原生 `--http`，但 **Kelivo 真机首轮没跑通这条新路线**（2026.08.03，响应形态像 SSE，怀疑打到的仍是桥，排查中） |
| Operit（闭源手机前端） | **外部实测五工具可用，写回后跨新会话仍能检索命中，本项目未复现**。可在 Android 的 proot Ubuntu 中由客户端按 stdio 拉起；人格不会自动注入，需要手工粘贴 |
| 自建前端（`--client generic`） | **出货档和注入契约有了，但我们没有验过任何一个自建前端**——注入那一半是你写的，契约五条成不成立只有你自己 diff 请求体才知道 |

### ChatGPT Plus + Zeabur

ChatGPT Plus 不能直接启动本地 stdio MCP，但可以通过私有自定义 GPT 的
Actions 调用 HTTPS API。仓库提供零第三方依赖的
`src/chatgpt_action_server.py`、根目录 `Dockerfile` 与完整部署说明：
[`docs/ChatGPT-Plus与Zeabur部署.md`](docs/ChatGPT-Plus与Zeabur部署.md)。

这条路的隐私边界是硬约束：公开仓库和镜像只放通用代码；人格文件、
`memory/`、会话线索与所有密钥只能进入私有持久卷和宿主环境变量。


**接入不确定时，先跑这两条**：不同客户端分别怎么接，见 [`docs/快速上手.md` §3c](docs/快速上手.md#3c-哪些客户端能接哪些不能以及聊天窗口那格的现状)；已经部署好、想确认它到底读到了什么，跑 `python src/mcp_server.py --doctor --corpus <你的语料目录>`——**只读**，打出读的绝对路径、进库多少块、时间范围、分层与时间戳来源分布，一眼看出是没跑通还是只是目录名不同。
已知的诚实边界都写在代码的 docstring 里——哪些翻译器跟真实导出核对过、哪些还没有，哪些参数是经验值待调，都标着。
