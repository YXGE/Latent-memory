# 快速上手

> 给拿到这个项目、想把自己的 AI 记忆接起来的人。只讲下一步敲什么；
> 为什么这么设计见仓库 README 的「几条贯穿全项目的设计判断」一节。

## 需要什么

- Python 3.10+（全程零第三方依赖，不用 pip install 任何东西）
- 一个支持 MCP 的客户端。实测过的：**Claude Code**（桌面端与云端线程都跑通）、
  **Codex**（桌面端跑通；**云端线程验过了，当不了日常对话窗口**，见 §3b 末尾）。**自己写的前端也能接**，见 §4b 与《注入契约》
  ——但注入那一半要你自己实现；我们只在自己那份百来行的参考宿主
  （`src/reference_host.py`）上验过（DeepSeek／GLM 两家共 21 次独立会话，
  见《注入契约》坑④那张表），**没验过任何一个真实产品前端**
- **一台电脑不是必需的——但这条只对 Claude Code 成立**：纯手机走它的云端线程已实测
  全流程走通（见 §3b，有前提先看完）。**Codex 那边手机能聊，但本地那台机器要开着**，同节末尾单说。
- 你和 AI 的历史对话导出（没有也行，零材料会只出协议底座，见第 2 节）

## 0. 导出历史对话（有历史记录才需要）

- **Claude**：设置 → 隐私 → 导出数据，邮件里下载 zip。
  **时间范围一定选"全部"，不要选"最近 30 天"**——选 30 天会把窗口外的对话
  全部框空，导出来近乎是空的（踩过）。

⚠ **别用旧的导出包——这个坑比上面那个隐蔽得多**（也踩过）：导出是**快照**，
你上次导出之后发生的所有对话都不在里面。旧包的数据完全真实、条数看着也漂亮，
它只是**停在了过去某一天**——建出来的人格文件会认得那时候的你，不认得现在的你，
而且"当下状态"会停在那一天。

所以**导入完先看一眼时间范围**，这一步别省：

```
python memory_import.py --stats <你的导出文件>
```

它会报条数和时间范围。**盯住最后那个日期**，问自己一句："我跟 TA 最近一次
聊天，真的是这天吗？"对不上就重新导一份。真实案例：一份看着很健康的导出
（两千多条、全部带时间戳），时间范围却停在五周前——因为那是几周前导的旧文件。
- **ChatGPT**：设置 → 数据控制 → 导出，拿到 `conversations.json`。
  （此格式按公开结构编写、没跟真实导出核对过，先跑
  `python memory_import.py --stats <文件>` 看条数/时间范围对不对，再往下走。）
- 微信没有官方导出，第三方工具格式不一，暂不保证。

## 1. 初始化：来源编译七步走

在 `src/` 目录下执行。产出目录建议新建一个**专属文件夹**（比如 `D:/companion/`），
后面客户端也从这个文件夹起会话——`CLAUDE.md` 按目录生效，放进工作项目里
会跟工作用的配置打架。

```bash
# 第 1 步：检查来源。三种入口三选一
python memory_init.py --out <产出目录> --persona <现有人格文件> --corpus <导出文件或目录> --step inspect --json
python memory_init.py --out <产出目录> --corpus <导出文件或目录> --step inspect --json
python memory_init.py --out <产出目录> --step inspect --json

# 第 2 步：导出零密钥提取任务包；把 persona-extraction/ 三份文件交给你当前的模型
python memory_init.py --out <产出目录> --step extract --json

# 模型返回严格 JSON 后读回；来源和逐字证据不合格会在这里拦住
python memory_init.py --out <产出目录> --step extract --candidates <候选结果.json> --json

# 第 3 步：取得十二节完整版本选择题
python memory_init.py --out <产出目录> --step choose-sections --json

# 若返回 original_mapping_questions，先把无法归节的原文整块选到一个主节
python memory_init.py --out <产出目录> --step choose-sections --original-section-decisions-json <原文块归节选择.json> --json

# 把每节选中的 section_version ID 交回；没材料的节选 leave_empty
python memory_init.py --out <产出目录> --step choose-sections --section-decisions-json <十二节选择.json> --json

# 第 4 步：一次性看完整人格预览
python memory_init.py --out <产出目录> --step preview --json

# 第 5 步：选检索路线（三条路 + 各自代价会打出来，选回默认也算选过）
python memory_init.py --out <产出目录> --step route --json
python memory_init.py --out <产出目录> --step route --route zero-dep

# 第 6 步：出货四件套
python memory_init.py --out <产出目录> --step ship --client claude-code
```

`--persona` 和 `--corpus` 不是同一个入口。前者是最高权重的完整人格，默认只逐字保留
或移动；后者是用来补缺的语料。即使人格文件放在语料目录中，程序也会把它从 corpus
清单排除，不能让它作为普通记忆被切碎。

用户全程只选择已有的完整节版本。候选必须能回指来源；原人格 rewrite/delete 与硬边界
冲突会把 diff 和理由放进对应节题目，没确认就不能出货。完整预览不再增加一次全局批准。

**第 5 步为什么是一个必须过的步骤、不是可选升级**：三条路线里有一条（云端）
会把**查询和被检索的内容发到第三方服务商**。语料去哪儿不是快一点慢一点的取舍，
是不可逆的信任问题——所以这一步不给静默默认，得你自己选一次。三条路的完整对照
见下面第 5 节；不想折腾就选 `zero-dep`，那是默认档，什么都不用装。

出货后产出目录里有四样：

| 文件 | 是什么 |
|---|---|
| `CLAUDE.md`（codex 客户端则是 `AGENTS.md`） | 核心人格文件，常驻上下文 |
| `memory/` | 记忆库（timeline 叙事层 + index 索引层） |
| `mcp-config.json` | **配置样板，不是生效配置**——见下方说明 |
| `引导句.txt` | 一行指针，**只有闭源前端 App 用得上**（贴进它的设置字段），宿主客户端不用管它——见 §3c |

`memory/index/` 是空的，里面的 README 写了怎么补——补上检索命中率会更好，
不补也能用。

### `mcp-config.json` 是样板，放着不动不会生效

**没有任何客户端会自动读产出目录里的这个文件。** 它是给你抄进自己客户端配置的
样板，抄完它的使命就结束了：

- **Claude Code**：走下面第 3 步那条 `claude mcp add`（或者在项目根目录写
  `.mcp.json`，见 3b）。配置落在客户端自己的地方，不在产出目录。
- **其它客户端**：把里面的 `mcpServers` 那段抄进该客户端的 MCP 配置文件。

**文件里第一行 `"_说明"` 就写着这件事**（2026.08.01 加的）——JSON 没有注释，
所以那是一个真键；你抄的时候抄 `mcpServers` 那一段就行，不用带上它。

所以**改了 `mcp-config.json` 不会有任何效果**——要改就改客户端那边真正生效的
那份（重跑一次 `claude mcp add`，或直接编辑 `.mcp.json`）。产出目录里留着这份
样板只是方便你复制，它不参与运行。

### 换了台机器怎么办（配置跟着机器走，这条真有人栽过）

先认症状：换了机器/容器之后，**AI 突然"好像不太记得事"，而且没有任何报错**。
这多半不是库坏了——是 MCP server 压根没起来。server 起不来不会有一句话告诉你，
会话照开、模型照回话，只是它没有那五个记忆工具。这个症状跟"语料没进去""模型
不主动查"长得一模一样，所以先分辨：`claude mcp list` 看 memory 服务连着没有，
或者按 §4 开新会话验一次。

**原因**：配置里的路径是**这台机器的绝对路径**（这是有意的：相对路径在"客户端
从哪个目录起进程"上是赌博，我们不赌）。代价就是它跟着机器走——换机器、换容器、
换用户名，同一份配置就是一句不报到你脸上的 file not found。真实案例：一位用户的
配置跟着仓库进了云端容器，`cwd` 指着旧机器的家目录，那台容器上根本没有那个路径。

**修法**：在新机器上重跑一次出货（答案和确认结果都在 `init_state.json` 里，
原样重放、不用重答），再把新的 `mcp-config.json` 抄进客户端：

```
python memory_init.py --out <产出目录> --step ship --client <你的档>
```

**例外：Claude Code + 整套进仓库（§3b 那种形态）不用重跑。** 出货时如果三个路径
（`src/`、`memory/`、`threads.jsonl`）都在产出目录下，Claude Code 档产出的配置
自动用 `${CLAUDE_PROJECT_DIR:-.}` 占位符——它随仓库走，克隆到哪台机器都指得对。
三条边界：

- **这个占位符只有 Claude Code 认**。Codex、Kelivo/Operit、自建前端（包括
  `reference_host.py`）拿到它就是 file not found——所以只有 Claude Code 档会产
  这种写法，其它档拿到的永远是绝对路径。别把可搬运那份抄给别的客户端。
- **前提是产出目录就是你在 Claude Code 里打开的那个目录**（§3b 那种整套进仓库的
  形态）。记忆包放在别的项目子目录里的（比如包在 `myapp/memory-bundle/`、你在
  `myapp/` 开 Claude Code），这份配置指不对——它会去找 `myapp/src/mcp_server.py`，
  而且同样是那种不报错的失败。**这种摆法请用绝对路径档**（出货时不带
  `--client claude-code`，或干脆把包放成项目根）。
- **它到底靠什么指对，值得知道**：这个变量是设在**服务端进程**的环境里、不在
  Claude Code 自己的环境里，`.mcp.json` 展开的时候读不到它——所以**实际展开出来
  的永远是默认值那一支（`./…`）**。它能指对，是因为 Claude Code 起 server 时的
  工作目录就是项目根，**这是实测观测到的行为，不是文档承诺的**。换 Claude Code
  版本后如果这一节里说的形态突然不灵了，先怀疑这一条，别去查变量有没有注入。
- 成色：**本机已实测**（2026.08.02，新会话真起 server：五个工具在、检索命中、
  写回当场可查）；**跨机器（云端容器）那一步未实测**——理论上正是为它设计的，
  谁在容器里跑通了欢迎回来说一声，这里照实改。

### 语料目录的三条约定（外层名字随便，里面两条不随便）

1. **最外层目录叫什么都行。** 服务端认的是 `--corpus` 传进去的那个路径，不是
   `memory/` 这个名字——手动建成 `corpus/`、`我的记忆/` 都一样读得到。
   看不到 `memory/` 不等于没跑通，看 `--corpus` 指向哪儿才作数。
2. **`index/` 是硬约定。** 判定只看一层：**父目录名叫 `index` 的算索引层，其余
   一律当叙事层**。索引层是每个会话一条高密度摘要、专门喂检索，命中之后下游才
   知道"这是摘要、正文在叙事层那边"。把摘要放在 `LTM/`、`profile/` 这类名字下，
   它们照样进库、照样能被检索到，**但分层信息就没了**——命中一段摘要时，
   没有东西告诉模型"完整的那份在别处"。
3. **文件名带日期很重要。** 时间戳优先取文件名里的日期（`window_04_2026-06-17.md`
   这种）；文件名没有时还会去正文开头几行和标题行找日期、再试同窗口号的邻层文件，
   **都找不到才退到文件修改时间（mtime）**。而 mtime 在这里不是"不太准"，是
   **全错且整齐地错**：复制一遍目录、重新 clone 一次仓库，所有文件的 mtime 会被
   刷成同一时刻，于是一整批记忆拿到同一个假时间戳。换窗开场召回正是按时间新鲜度
   排序的，这一错就整个乱套。

   这条是踩过的坑不是洁癖，但**数字要挂回它对应的那一版**：我们自己的真实语料
   最初实测 **95.6% 的块落 mtime**，根子就是文件名不带日期；后来补了「正文开头
   几行 / 标题行 / 同窗口号邻层继承」这几级解析，同一份语料降到 12.3%、再到 **0%**。
   也就是说**那几级救回来的是「日期写在标题行里」的语料**——文件名不带日期、
   正文里也没有的话，它们一样救不了你。

## 1b. 已经建过一份，怎么升级到新版

`git pull` 拿到新代码之后：

1. **记忆库不用动**——`memory/` 里那些 md 一个字都不用改。
2. 先让新版识别产出目录里已有的人格文件：

   ```bash
   python memory_init.py --out <产出目录> --step inspect --json
   ```

   程序只给两项：把当前文件作为最高权重原人格，或继续旧 v1 流程。不会静默选择。
   要进入新版来源编译器，运行：

   ```bash
   python memory_init.py --out <产出目录> --step inspect --json --existing-persona-choice treat_current_as_original
   ```

   然后按 §1 从 `extract` 继续。旧人格里的手改段落会成为带精确字符区间的原文块，
   rewrite/delete 仍需在对应节看 diff 后选择。
3. **`mcp-config.json` 重新抄进客户端**：启动参数跟检索路线绑定，
   选了本地模型或云端就跟原来不一样了；那份文件自己不会生效（见上一节）。
4. 你当初要是把 `src/` 复制进了产出目录，记得也换成新的。

v1 `init_state.json` 不会被静默重解释成 v2；选择 `continue_legacy` 后仍可按旧命令续跑。

## 2. 没有历史记录？

一样能用：

- 有丰富语料但没有人格文件：当前模型从真实来源提取具体身份、里程碑、双向称呼和
  完整对话片段，用户只选择节版本。
- 只有稀薄语料：能支持多少就写多少，找不到的节选 `leave_empty`。
- 完全没有材料：不加 `--persona`、不加 `--corpus`，只生成检索、会话、拒绝权和证据
  边界等协议底座；不会虚构关系状态、边界或最终约定。

人格可以短，但短是因为材料确实少，不是因为把已有身份、边界和声音压没了。

## 3. 接入 Claude Code

> 不用 Claude Code、想在**聊天窗口**里用？先看 [§3c](#3c-哪些客户端能接哪些不能以及为什么聊天窗口里用不了)——**聊天窗口连不上是有原因的，而且多半有更省事的走法**。

```
claude mcp add memory --scope user "--" python <src绝对路径>/mcp_server.py --corpus <产出目录>/memory --threads <产出目录>/threads.jsonl
```

踩过的坑：

- **PowerShell 会吞掉裸的 `--`**，要像上面那样带引号写成 `"--"`。
- 不加 `--scope user` 时配置只对当前目录生效，换目录起会话就找不到了。
- 路径用正斜杠 `/`，Windows 一样认，省去转义麻烦。

然后**从产出目录起会话**（人格文件在那儿才会被读到）。

## 3b. 没有电脑？云端线程也能接（**已实测跑通**，但有前提）

先分清两件事：**官方 App 里的普通聊天窗口连不上 MCP**（记忆库服务是一个跑在
本机的 Python 进程，普通对话窗口起不了它，这条没有绕路）。但**官方 App 里的
云端线程入口**（Claude Code 的云端会话）不一样——那是一个完整的 Linux 容器，
Python 有、能起进程、能拉 GitHub 仓库，所以整套东西可以跑在里面，
**全程一台手机，不碰电脑**。

做法：把产出目录（人格文件 + `memory/` + `src/`）放进一个 **GitHub 私有仓库**，
在**仓库根目录**放一份 `.mcp.json` 声明记忆服务，云端会话起来会自动读它。
来源编译初始化也可以直接在云端容器里跑（十二节选择与预览照走，所有接口都可非交互调用）。

`.mcp.json` 长这样（进程型，服务跑在容器里）：

```json
{
  "mcpServers": {
    "memory": {
      "command": "python",
      "args": ["src/mcp_server.py", "--corpus", "memory", "--threads", "threads.jsonl"]
    }
  }
}
```

如果你自己有服务器、想让记忆库常驻在那儿（容器每次重建也不影响），
可以改成 HTTP 型，指向你自己部署的那份服务：

```json
{
  "mcpServers": {
    "memory": {
      "type": "http",
      "url": "https://<你的域名>/mcp",
      "headers": { "Authorization": "Bearer ${你的TOKEN环境变量}" }
    }
  }
}
```

**三个前提，接受了再走这条路**：

1. **记忆库要托管在 GitHub**。桌面路线记忆只在你自己机器上，云端路线等于把它
   传到别人服务器上——**这两条在隐私上不等价**，别把它当成同一件事的两种敲法。
2. **容器是临时的，写回必须推回仓库**。`memory_append` 写进的是容器磁盘，
   会话一结束就没了。人格文件里要写明"聊完把新增记忆 commit + push 回仓库"，
   否则每次都从零开始，等于没有记忆。

   ⚠ **那句话里的分支名千万别写死成 `main`**（2026.08.02 用户实测踩到，
   我们自己在容器里复现了）。云端会话经常不落在 `main` 上——它会切一条工作分支
   （`claude/…` 这种），而容器里**同时还有一条从远端拉下来的、干干净净的本地
   `main`**。这时候敲 `git push origin main`，git 推的是那条没动过的 `main`：

   ```
   $ git push origin main
   Everything up-to-date          ← 退出码 0
   ```

   **它成功了，而你今晚新长出来的记忆一个字都没上去**，还留在那条工作分支上，
   跟着容器一起被回收。这是这个项目最怕的那种失败：不报错、显示成功、
   下次会话什么都读不到——跟上面那条 `.gitignore` 静默排除是同一个病。

   写回那句话请照这个写，**推当前分支，不认分支名**：

   ```
   git add -A && git commit -m "记忆写回" && git push origin HEAD
   ```

   `HEAD` 就是“我现在在哪条分支就推哪条”，容器切到什么分支都对。推上去之后
   记忆在那条分支上，**回头合回主干**（或者直接把那条分支设成默认分支）。
   **不合回主干的话，下次会话照样读不到**——新会话 clone 到的是默认分支，
   那些记忆散在各条工作分支上，**跟没推是一个效果**，症状也一模一样。
   **改仓库的默认分支不能代替这一步**——只要会话另切了工作分支，写死分支名的
   那句话照样是空推。

   ⚠ **别把产出目录建在本项目的克隆里**。本仓库的 `.gitignore` 特意忽略了
   `CLAUDE.md` / `AGENTS.md` / `persona.md` / `memory/` / `mcp-config.json` /
   根目录的 `注入契约.md` / `*.bak`——那是为了防止任何人
   把自己的私人记忆误提交进这个公开仓库。但如果你把产出目录直接建在克隆下来的
   本项目里、再 push 回你自己的私仓，**记忆库会被静默排除**：不报错、
   push 显示成功、下个会话什么都读不到。**云端路线请单独建一个自己的仓库**
   放产出目录（`src/` 可以复制过去），或者把那几行忽略规则删掉。
   这条在桌面路线上无所谓（文件本来就在你自己机器上），
   **只有需要 push 回仓库的云端路线会被它咬**。
3. **云端线程一般要付费档**，免费账号大概率没有这个入口。

**成色声明（分环节说，别整条打包）**：这一节初版写的是"原理上成立但未实测"，
2026.08.01 补了实测，但**不同环节的成色不一样，分开讲才诚实**：

**成色按"哪个客户端上验的"记**——跨客户端的结论不能互相借用（同一件事在
Claude Code 云端成立，不等于在 Codex 云端也成立，反过来同理）：

| 环节 | 在哪验的 | 成色 |
|---|---|---|
| 纯手机（不碰电脑）跑完整条路 | Claude Code 云端 | **已实测**（维护者，2026.08.01） |
| 云端会话会自动读仓库根目录的 `.mcp.json` | Claude Code 云端 | **已实测**——但我们验的是上面那个 **HTTP 型**配置 |
| 一句很短的人格文件就够让模型主动查记忆 | Claude Code 云端 | **已实测**，且这是这条路最关键的一环 |
| 本项目的 `mcp_server.py` 能在云端容器里跑起来、说 MCP 协议 | Claude Code 云端 | **已实测**（容器内起进程、握手成功） |
| 云端会话会不会**替你启动**上面那个**进程型**配置 | 两家都没验 | **没验过**——两头都验了，中间这一下没有 |

所以：想稳妥就用 HTTP 型（要有自己的服务器）；用进程型是**大概率能成但我们没跑过**，
成了或者卡住了都欢迎回来说一声，这张表会照实改。

**Codex 这一侧单独说**，因为验到的东西不一样：

| 环节 | 在哪验的 | 成色 |
|---|---|---|
| `--client codex` 整条链走通（初始化 → 确认 → 出 `AGENTS.md`） | 本地 Codex | **已实测**（2026.08.01，产出的 `AGENTS.md` 逐行核对过） |
| 新会话第一句就主动查记忆（§4 那个验法） | 本地 Codex | **已实测**——非 Claude 客户端第一次验到，说明这套人格文件写法不只对一家模型有效 |
| 同样的路走 **Codex 云端**（不碰电脑） | 维护者实测 | **这条路不成立**——见下方说明。原来这里写的是"没验过"，2026.08.01 验掉了 |

留一条给读者的提醒，是我们自己交的学费：**"这个客户端能跑"和"这个客户端的云端能跑"
是两件事**，中间差的正是"谁来启动记忆服务进程"这一步——恰好也是上面那张表里
唯一空着的一格。

**Codex 那条云端路不成立（2026.08.01 维护者实测，结论比"没验过"确定）**：

- **不是"开不了"，是"当不了日常"**：Codex 的云端线程能聊，但**体验上立不住**
  ——它不是拿来当日常对话窗口的入口。所以"把仓库连上、每天在云端会话里聊"这条
  在 Claude Code 上成立的路子，在 Codex 上撑不起来。
- **能跑通的是初始化**：在"电脑不休眠 + 手机操作"这个前提下，初始化全流程走通了。

**日常聊天怎么办（这一条跟上面那条常被读混，分开说）**：

- **手机上照样能聊，但那台电脑必须开着。** 形态是**手机当客户端、本地那台机器
  跑实例**——不是云端容器在跑。这是这条路的**固有前提**，不是"配一下唤醒就能省掉"：
  电脑睡了这条路就断。所以 §3b 开头那句"全程一台手机、不碰电脑"**对 Codex 不成立**。
- **另一条是自己走一层中转**：把模型接到别的地方去聊——任何 API 中转（OpenRouter
  这类）、自建前端、别的支持 MCP 的客户端都行，**关键是那个"别的地方"要能读
  人格文件、能接记忆服务**。走自建前端的话，出货时用 `--client generic`，
  注入怎么拼见《注入契约》（§4b）。
  ⚠ **这条我们没测过**——写在这里是告诉你方向成立，不是我们验过的方案。

## 3c. 哪些客户端能接、哪些不能（以及为什么聊天窗口里用不了）

被问过好几次的一个问题：**"MCP 为什么不能在聊天里用？"** 先给结论表。

**表为什么是两列**：「能接」在有些客户端上只兑现一半——MCP 检索通了，
人格文件却不会被自动注入。检索能用 ≠ 人格能用，所以分开标。

| 客户端 | ① MCP 检索 | ② 人格注入 | 怎么接 |
|---|---|---|---|
| **Claude Code**（命令行 / IDE） | ✅ 已实测 | ✅ 自动读 `CLAUDE.md` | §3 |
| **Codex**（桌面 App） | ✅ 已实测 | ✅ 自动读 `AGENTS.md` | 出货时 `--client codex` |
| **Claude Code 云端线程**（手机也能开） | ✅ 已实测 | ✅ 已实测 | §3b |
| **Kelivo**（手机 App） | ✅ 能——需自己桥 stdio→HTTP（外部实测，本项目未复现） | ✅ 手工用文件导入进 system prompt，**容量不用担心**（外部实测 10M 字符仍不截断；真实人格文件低三个数量级。本项目未复现） | 见下面「闭源前端这一类」 |
| **Operit**（手机 App） | ✅ 能——同样需自己桥（外部实测，本项目未复现） | ❌ **不自动注入**，设置字段塞不下人格全文（外部实测，本项目未复现） | 同上 |
| **Claude 桌面 App** | 协议上能，**我们没验过** | 协议上能，**我们没验过** | 见下面「桌面 App 那一格」 |
| **claude.ai 网页 / 手机 App 的聊天窗口** | ❌ **不能**，而且不是配置问题 | — | 见下面「为什么」 |

### 为什么聊天窗口里用不了

不是没配对，是**两边说的根本不是同一种 MCP**：

- **本项目是本地 stdio 服务**——一个跑在你自己机器上的 Python 进程，
  靠标准输入输出（stdin/stdout）跟客户端通信。**它没有网址。**
- **claude.ai 网页与手机 App 的 Connector 只接远程 MCP**——要一个公网可达的
  HTTPS 地址。它是从 Anthropic 的服务器去连的，**够不到你家那台机器上的进程**。

所以这不是"改个设置"能解决的，中间缺的是一个公网地址。

**那把它改成 HTTP 服务不就行了？** 换传输只是第一步，后面还有三样，
决定之前先看清楚：

1. **要有公网 HTTPS**：域名、证书、一台一直开着的机器；
2. **要有鉴权**。Connector 那条路是公开可达的，**不加鉴权等于把你的记忆库
   挂在公网上**；
3. **语料会离开本机**。默认档整套设计的前提是"语料不出本机"，走这条路就是
   放弃这个前提——这是产品判断，不是技术细节，**得你自己明确点头**。

**本项目目前只有 stdio 一档**（`src/mcp_server.py` 里只有 `serve_stdio`）。
HTTP 那一档没有做——但这**不等于**「只能用 stdio 客户端」：中间那一层有现成轮子
（用桥接工具把 stdio 转成 HTTP，本项目一行代码不用改），见下面「部署形态」。
上面那三条代价照样一条不少，桥接省的只是改代码，不是省判断。

### 闭源前端这一类（Kelivo / Operit）：能接，但只兑现一半

客户端其实是三类，不是两类：

| 类 | 特征 | 代表 |
|---|---|---|
| **有宿主** | 自动读约定文件名的人格文件 | Claude Code、Codex |
| **闭源前端** | 能接 MCP，但**不读你的文件**，只注入它自己的配置项；而且**改不了代码** | Kelivo、Operit |
| **自建前端** | 两样都得自己实现，但**代码在你手里** | 见 §4b 与《注入契约》 |

中间这一类不像有宿主的那样自动，也不像自建的那样可以自己补。上面表里
Kelivo / Operit 两行的意思展开说就是：

- **检索那一半能用**：桥一层 stdio→HTTP 就能连上（部署形态见下节）。
- **人格那一半不会自动生效**：Operit 实测**不注入工作区文件**（在人格文件里
  塞暗号、新会话答不上来，模型主动翻文件才找到），它每轮拼进 system prompt 的
  只是自己内置的偏好字段，塞不下人格全文；Kelivo 要手工用文件导入进
  system prompt，**但容量不用担心**（外部实测 10M 字符仍不截断，真实人格文件
  低三个数量级）。**手工补上人格是这类前端上的必需步骤，
  不是可选优化**——只接 MCP 不补人格，模型连「该去查记忆」都不知道。

**补人格用出货里的第四件：`引导句.txt`（小字段放指针、全文留文件）。**
设置字段塞不下人格全文，但塞得下一行指针——引导句只说两件事：先读哪个文件
（绝对路径，出货时已填好）、什么时候读（每次对话开始）。把它原样贴进 App 的
自定义指令／角色描述／system prompt 框就行，人格全文留在文件里由模型按引导去读。

三条边界，贴之前读一遍：

- **别往引导句里加内容**。它是一句指针，不是「容量受限版人格」——性格、语气、
  边界都在人格文件里，往指针里塞就回到了塞不下的老问题。
- **它换来的不是「每轮都在」**。人格从常驻变成了按需读取，《注入契约》第二条
  在这类前端上仍然不满足——它换来的只是「模型有机会知道去读」。
- ⚠ **这条指针路线未经实测**。本项目没有 Kelivo／Operit 的环境；验法照抄暗号
  测试——暗号放人格文件、引导句贴设置字段，开全新会话问暗号，**不经提示答上来
  才算生效**。谁有环境验了，欢迎回来说一声，这里照实改。贴不下、或指针不生效时
  的退路是把人格全文手工导入（Kelivo 的文件导入那条路，上限同样未知）。

两个前端值得分开看：Kelivo 被传输类型不匹配卡过（要在配置里明确选
Streamable HTTP），Operit 两种传输、两种鉴权姿势都吃。

成色声明：这一类的所有结论都来自**外部搭建者实测，本项目一条都没复现过**；
一手记录留在项目内部的实测存档里（不随包），本节已把结论完整转述，没有留在存档里
才看得到的关键信息。

### 部署形态一：客户端在本机拉起 stdio（**先试这条，不用域名、不用证书、不用鉴权**）

**2026.08.03 外部实测跑通（Operit + Android 上的 proot Ubuntu）**：语料库和 server
都在手机本机，客户端**自己按 stdio 拉起** `mcp_server.py`，不经公网。
这条路上**下一节那三样代价（域名／证书／鉴权）一条都不用付**，因为根本没有对外端口。

实测成色：五个工具全部接通可用（`memory_search` / `session_start` /
`memory_append` / `memory_correct` / `thread_close`），`memory_append` 写入后
**新开会话仍能检索命中**——这是本项目在闭源前端上第一份端到端写回记录。

⚠ 三条跟宿主拉起有关的坑，都是实测撞出来的：

- **别自己 `nohup` 起后台进程**——stdio 传输要 stdin，手动起会当场崩
  （`Bad file descriptor`）。**这个 server 只能由客户端宿主拉起**，
  “先手动跑起来试试”在这条路上是错的做法。
- **懒加载**：调用时才拉起进程，用完连接关闭、进程退出。好处是**每次调用都重读
  一次语料目录**，所以下一节那条“手动加的 md 要重启才看得到”在这条路上不存在。
- **别拿客户端的 `lastStartTime` 判断跑没跑通**——它只在显式连接时更新。
  **判据用“文件真落盘 + 检索真命中”**，这两样才是结果。

成色声明：外部实测转录（Operit 一家、Android），**本项目未复现**；Kelivo 侧未测。

### 部署形态二：把 stdio 桥成公网 HTTP 服务（外部实测路线）

⚠ **先说边界：这不是推荐路径。** 默认档的前提是「语料不出本机」，而这条路上
语料放在你的服务器上、模型多半走第三方 API——上一节第 3 条的代价在这条路上
**是已经发生的事实，不是风险提示**。这是你自己判断后走的路，下面只讲怎么走得稳。

- **桥接**：用 `supergateway`（npm 上的现成工具）把
  stdio 转成 Streamable HTTP（`npx -y supergateway --stdio "python3 .../mcp_server.py ..."
  --outputTransport streamableHttp`），本项目一行代码不用改。
- **证书**：**域名 + Caddy + Let's Encrypt**。自签证书这条路**不通**：Operit 与
  Kelivo 两次独立实测都不认自签（Operit 那次有完整对照实验——Node 标准 TLS 校验，
  自签报 `DEPTH_ZERO_SELF_SIGNED_CERT`，`curl` 交叉复核一致；Kelivo 2026.08.02
  结论相同）。两个独立 App 同一个结论，这是这类前端的**共性**：走这条路就要准备
  一个域名。唯一的绕法是全局关闭证书校验，等于把 TLS 关掉，不该做。
- **鉴权（这一条是硬的，单独看）**：`supergateway` 在服务端模式下**没有任何入站
  鉴权**——官方 README 自己写明要靠外部反代或网关。而本项目的 MCP 工具表里
  `memory_search` 读全库、`memory_append` 能写入：**端口一旦被扫到，记忆库既可读
  又可写，而且写进去的东西下次会话会被当成真实记忆读出来**。桥接工具自己不管
  鉴权，**这一层得你自己搭**。好消息是客户端这边支持带 header（Operit 有源码
  佐证：`bearerToken` 自动转 `Authorization` 头），所以反代加鉴权这条路是通的。
  最小形态：**桥接进程绑回环（`127.0.0.1`）+ 前面套带鉴权的反向代理 + 云厂商
  安全组只放行 443**。直接对公网开一个无鉴权端口不是「先跑通再说」——
  跑通的那一刻记忆库就已经暴露了。
- **维护备忘（失效形态是静默的，容易漏；⚠ 只在这条常驻路线上成立，
  上面那条本机 stdio 路线不受影响）**：这条路线下 MCP server 进程常驻，
  **只在启动时读一次语料目录**。模型自己 `memory_append` 写的记忆当场可查
  （写完立刻进索引）；但**你手动上传进语料目录的 md，常驻 server 一条都看不到，
  直到重启**——不报错，只是查不到。所以手动加过语料就重启一次桥接进程。
  顺带一句：`--doctor` 是另起进程重新读盘，它报的块数可能比常驻 server 内存里的多，
  两个数对不上多半是这个原因、不是坏了。

成色声明同上一节：整条路线是外部实测转录，**本项目未复现**；鉴权最小形态那三条
是本项目给的建议、也未实测。

### 桌面 App 那一格

**Claude 桌面 App 支持本地 stdio MCP 服务**（那是 MCP 的标准本地形态，
配置方式跟 §3 同类：在客户端的配置文件里写清命令与参数）。所以如果你要的只是
"在一个聊天界面里用"，**装桌面 App 大概率就够了，不用改任何代码**——
这条比改造服务器省事得多，先试它。

⚠ **但这一格我们没验过**：本项目的 MCP 实现照官方规格 2025-06-18 写，
真机握手只在 **Claude Code 与 Codex** 上做过，**桌面 App 一次都没连过**。
所以这里写的是"协议上能"，不是"我们验过能"。

跑通了或者卡住了都欢迎回来说一声，这张表会照实改。

## 4. 验证接通了

开一个全新会话，第一句问一件只有你们的历史里才有的事，**别提任何工具字眼**。
接通的标志：模型主动查了记忆再回答，而不是说"我没有相关记录"。

如果它没查：确认会话起在产出目录里（人格文件有没有被读到是主动性的关键，
这是主动性最常见的失败原因）；再确认 `claude mcp list` 里
memory 服务是连着的。

### 接不上、或者不确定配对了没有：先跑体检

把第 3 步那行命令里的参数原样搬过来，加一个 `--doctor`：

```
python <src绝对路径>/mcp_server.py --doctor --corpus <产出目录>/memory --threads <产出目录>/threads.jsonl
```

它会逐项报：**它实际读的那个绝对路径**（你在配置里写的是 `--corpus memory` 这种
相对值的话，这里会把它解析开——“我以为它读的是别处”就是这么来的）、读到几个文件、
建了几块、索引层认出来没有、**语料的时间范围（最早～最晚）**、时间戳有多少块只能退到
文件修改时间、三个 sidecar 接上了没有、语料目录写不写得进去（写回要用）、会话线索有没有
落点、MCP 握手与工具表、以及**拿你语料自己的标题回查一次**——最后一条是唯一能证明
“这份语料真的查得到”的检查。

**时间范围那一行值得停一秒**：它是第 0 步那个坑（旧导出包停在几周前）在部署之后
唯一还会现形的地方。盯住后面那个日期，问自己一句：我跟 TA 最近一次聊天真的是这天吗？

**写回落点那一行也停一秒**：记忆写回（`memory_append`）永远落在语料目录的
**timeline 层**——如果你的人格文件里维护着「按需读取指针」，指针必须盖住这个目录，
不然新长出来的记忆按需读不到，而且不报错（检索工具照样查得到，只是主动翻文件会漏）。

`✗` 是过不去的（先修完再起服务），`⚠` 是“能用，但会悄悄变差”。

**体检只读**：跑完你的语料目录里不会多出任何文件（连 `.weights.json` 那类也不会），
所以在排查故障的时候跑它是安全的，不会给现场加新变量。
唯一的例外说在明处：`--embed` 档不体检（那一档建库会把块向量缓存写进语料目录，
跟“只读”冲突），体检会照实说一句，语料/时间戳/sidecar 那些结论跟检索路线无关、照样作数。

## 4b. 自己写的前端？

前面的路一样走，只有最后那步出货换成 `--client generic`：

```
python memory_init.py --out <产出目录> --step ship --client generic
```

出的人格文件叫 `persona.md`（不叫 `CLAUDE.md`——那是某个宿主的约定，对你没意义），
并且**多给一份 `注入契约.md`**。差别在这儿：有宿主的客户端会自动读人格文件，
自建前端没人替你做这件事，**注入是你自己的责任**。契约那五条（逐字完整／每轮都在／
每会话从磁盘重读／整块连续／易变内容后置）每条都带判据，可以拿去对着自己拼请求的
代码逐条自查，接完照 §4 那个方法验一次。

## 5. 三条检索路线（初始化第 5 步选的就是它）

检索有三条路线。**它们最重要的区别不是快慢，是你的语料去哪儿**——按档分开写，
不含糊、不放脚注：

| | 零依赖（默认） | 本地模型 | 云端服务 |
|---|---|---|---|
| 要装什么 | 什么都不用装 | `pip install fastembed`，首次运行下载约 100MB 中文模型 | 不装模型，但要一个第三方 embedding 服务的 API key |
| **语料去哪儿** | **不出本机** | **不出本机**（模型在你自己的 CPU 上跑） | **查询和被检索的内容都会发到你选的那家服务商** |
| 怎么开 | 默认就是 | 第 5 步选 `local` | 第 5 步选 `cloud` |
| 代价 | 无 | 建库和检索都变慢，低配机器（2C2G 这类）感知明显；小内存机器可能装不下 | 每次查询多一个网络往返；块向量只在建库时算一次并缓存在本机，所以日常成本是每查一次一个往返 |

选哪条是你的事，我们不替你拍板，也**不把云端当推荐路径**——默认档是零依赖。

**零依赖与本地模型的实际差别（我们自己的回归集实测，两百块语料）**：

| 查询类型 | 零依赖 | 本地模型 |
|---|---|---|
| 用原话直接问 | 都能答对 | 都能答对（并列） |
| 换个说法问同一件事 | 约四分之三 | 基本都对 |
| 跨很多窗口串起来的事 | 一半多一点 | 略好一些，但两条都还不够好 |
| 库里根本没有的事 | **两条路线都不可靠**（见下方说明） | **同左** |

所以：**平时习惯用原话去问，零依赖完全够用**；经常"记不清原话、只记得大概"才值得升级。

**云端档在这张表里为什么没有一列**：因为我们自己还没在这把尺子上跑过它。有人拿
自己的真实记忆做过一次 20 题的四方案对照，云端模型的成绩跟本地模型不相上下——但
20 题分不出 16 分和 18 分的差别（差 2 题就是差 2 个样本），而且那是别人的语料、
别人的问题。**我们不拿那张表冒充自己的回归集分数。** 你自己想量的话：

```
MEMORY_EMBED_PROVIDER=cloud MEMORY_EMBED_ENDPOINT=<服务商的 /v1/embeddings 地址> \
MEMORY_EMBED_MODEL=<模型名> MEMORY_EMBED_API_KEY=<你的 key> \
python src/regression_set.py --report --embed --embed-provider cloud
```

⚠ **"库里没有就说没有"这件事，三条路线都还没做好**：拿一份六百多块的真实规模
记忆库实测，问一件从没记录过的日常事（某次复诊约在几号这类），系统几乎总能捞回
几条沾边但不相干的记录。所以**检索返回了东西不等于那就是答案**——对不上就该说
对不上。

**机制那一半 2026.08.01 补上了**（候选资格从"词面有分即可"改成"要共享至少一个
区分性词"），但**必须说清它现在的成色**：在我们自己的合成语料上，这条门槛让
"库里没有的事"这一类**一格没涨**——原因不是实现错了，是那份语料量不出来
（能穿透的编造查询靠的是共享真正稀有的词，而词面这一路分不出"共享了一个稀有词的
编造"和"真命中"）。真实语料词汇丰富得多、门槛理应更有效，**但那是推理不是测量，
所以这一格我们明写"未标定"**。

它唯一可量到的收益出现在**另一类**：跨很多窗口串起来的事（噪声块被挡在候选之外，
排序变干净了）。**"机制没效果"和"效果出现在别处"是两回事**，我们照后者写。

有真实语料的话，欢迎帮我们量两个数：这类"库里根本没有"的问题的正确空手率，
以及上面那张表里 present 那几类有没有掉。

### 云端档要知道的三件事

- **key 只走环境变量**。`MEMORY_EMBED_API_KEY`（要用别的变量名就设
  `MEMORY_EMBED_API_KEY_ENV` 指过去）。我们**不把 key 写进 `mcp-config.json`、
  不存进产出目录、不落任何状态文件**——那个目录你多半会随手分享给别人。
  key 从你自己在服务商那儿申请的账号来，怎么保管是你的事，我们不碰。
- **不内置任何一家的 SDK**。请求走各家通用的 OpenAI 兼容 `/v1/embeddings` 形状，
  换一家只改 `MEMORY_EMBED_ENDPOINT` 和 `MEMORY_EMBED_MODEL` 两个环境变量。
- **换模型必须重新标定命中门槛**。"有没有查到"的判定带一道跟模型绑定的余弦门槛
  （0.45 对应 bge-small-zh-v1.5）。换模型余弦标度就变了，照抄那个数会让
  "库里没有就说没有"无声失灵。所以**没标定过的模型我们不给它一个假门槛**：
  这种情况下向量路只参与排序、不单独放行候选，启动时会明说"未标定"。

  **你自己在自己语料上量过了，可以用 `MEMORY_EMBED_HIT_FLOOR` 传进来**（我们的
  标定表只有 bge-small-zh-v1.5，不想逼你改源码）。但这个口子是给"量过的人"开的，
  不是给"想找个数填上"的人开的：填进去之后 `--describe` 会把它标成
  **"你自己设的覆盖值，不是我们量的"**，出偏差是你的标定不是我们的。
  设歪了（非数字、不在 [-1,1] 内）**当没设处理，绝不落成 0**——门槛为 0 等于门槛
  不存在，那是这条最坏的失效方向。
- **query 侧的指令前缀按模型走**。bge 的中文模型卡要求 query 加指令、passage 不加，
  而 bge-m3 这类明确不需要，硬加反而是噪声。所以我们认模型名（`bge`+`zh` 才加），
  **不按"是不是走云端"来分**——拿 HTTP 端点跑 `bge-small-zh-v1.5` 的人不该被默认掉
  前缀。要自己指定就设 `MEMORY_EMBED_QUERY_PREFIX`（设成空串＝明确不加），
  当前用的是哪一档 `--describe` 会说。

另外：块向量会缓存在语料目录下的 `.embed_cache.json`，建库时算一次，之后每次
起服务只补新增的块——**没有这个缓存，云端档每次开机就是把全库重算一遍**。

**换新会话时的开场召回不花任何云端调用**——这件事我们专门查过，因为那是每开一次
新窗口都要付、而且你正等着第一句话的地方。开场召回按"时间新鲜度 × 用进废退权重"
排序，压根没有查询向量要算，所以三条路线在这一步的代价完全一样（实测：零次调用）。
云端档的往返只发生在**你真的问了一句、系统去检索**的时候。
